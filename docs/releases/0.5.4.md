# CYDpod 0.5.4

Released 8 November 2026 for the JC2432W328C. 0.5.4 is 0.5.3 plus scrolling Now Playing labels and a corrected transmit power readback. The Bluetooth stack, volume handling, audio buffer and build kit are unchanged from 0.5.3.

## Changes since 0.5.3

**Scrolling Now Playing labels**
- A title, artist or album too wide for its row now scrolls. It holds for 1.5 s, scrolls through one full lap at about 33 px/s, then rests on its "..." form again. Only one label scrolls at a time, and labels that fit never move.
- ASCII labels are drawn a scanline at a time straight from the flash font, with no heap and no flicker. UTF-8 labels reuse the existing title strip, so the per-second time updates don't reload it from the SD card.
- Scrolling pauses while the audio buffer is low, during a seek preview and while a finger is on the screen. Each label stays inside its own row.
- Cost: +16 bytes of static RAM on each image. Details: `docs/research/player-marquee.md`.

**Transmit power readback**
- 0.5.3 asked for +6 dBm but logged `max=5` (+3 dBm). The disassembly of Espressif's controller shows the set is asynchronous: it queues a message to the controller task and returns at once, so reading the level back on the next line always showed the old value.
- CYDpod now waits up to about 20 ms for the controller to apply the level before logging it. The way the level is set is unchanged, so 0.5.3 was probably already running at +6 dBm; it just reported +3. Details: `docs/research/bt-tx-power.md`.
- The controller still adapts power within the configured range (0 to +6 dBm) when a speaker asks it to. Pinning it at +6 would be a separate change.

## Provenance

- The firmware was compiled from `2a7b1a0` on the trimmed libraries pinned as `bluedroidOverlay` in `dependencies.lock.json`, the same as 0.5.3. `FIRMWARE_VERSION` remains `1.2.0`.
- `v0.5.4` identifies the matching source on `main`. The changes after the firmware commit are documentation only.
- The build kit is 0.5.3's: the same toolchain, A2DP overlay and Bluedroid overlay.

## Checks

- **Software:**
  - Host suite (`tests/build_catalog.cmd`) PASS on the marquee commit, including the new `marqueeRegression`.
  - Release compile, `tools/check.ps1 -Board jc2432w328c -SkipProbe -SkipHostMedia -LargePcmRing -PcmRingFrames 6144`: PASS, both images built.
  - Static RAM: 79,668 bytes (Bluetooth) and 79,676 bytes (wired), 16 bytes above 0.5.3.
- **Owner board run:** the marquee build looked good in an informal owner run on the JC2432W328C. That was not a timed measurement.

## Not yet confirmed on hardware

- **This exact release image** has not been flashed. Its two changes were each built and checked separately.
- **The transmit power readback:** expected to show `bt: tx power rc=0 level min=4 max=6`. If it still shows `max=5`, the controller didn't apply the level within 20 ms.
- **Marquee:** UTF-8 labels, each screen rotation, AirPods Pro 2 and the wired build weren't checked separately.
- **Still open from 0.5.3:** occasional JBL dropouts from the radio link, the 21 KB lowest free heap seen once after Sleep, a track-change underrun around quick Next and seek presses, the touch interrupt, the ~4 s wake-to-sound target, wired hardware and enclosure fit.

## Flashing

0.5.4's boot files are byte-identical to 0.5.3's. From 0.5.2 or later, flashing `app.ino.bin` at `0x10000` is enough. Otherwise flash all four regions. Settings and pairings are kept either way; instructions are in the firmware archive README.
