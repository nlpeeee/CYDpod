# CY-116A1: bounded SD queue

API: `PlaylistQueue::{queueAt,queueFind,queueCount}` uses a descriptor
(path/count) and a 256-ID window; -1 means out of range, missing or short SD
read. `audio_setQueueSource(AudioQueueSource,n,keep,jump)` retains the callback
and caller-owned context, while `audio_setQueue` retains array/identity support.
Audio stops with `queue_unavailable` when a cursor read fails. The existing
order allocation and shuffle algorithm are unchanged.

Folder/favourites/M3U builders stream catalogue IDs to alternating
`/.sys/queue-{a,b}.ids` files, publishing only a completed stage. Folder and
favourite order, M3U duplicates/missing entries and the existing 1,000-entry
M3U limit are preserved. Read-only cards refuse new disk queues; All remains
available. Files close between window fills. Failed staging retains playback.

RAM (source arithmetic; hardware not measured): old resident queue IDs were
4,000 B at 2,000 tracks and 20,000 B at 10,000. New ESP32 cursor is 528 B (ELF symbol size 0x210)
(512 B IDs + descriptor), plus fixed builder/descriptor bookkeeping, below
1 KB at both sizes; growth with N is zero. Existing favourites CRCs, bounded
M3U key scratch (up to 4 KB), audio order and A2 staging are excluded.
