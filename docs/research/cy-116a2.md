# CY-116A2: bounded preview and view staging

Changes: Classic source lists retain a 256-ID PlaylistQueue, with alternating
`/.sys/preview-{a,b}.ids` files separate from the two live queue files. Cached
row lookup returns IDs by value; SD refill failure latches the existing error
row until reload. Selection copies the preview into the inactive live file;
only a completed stage changes playback. Catalogue playView uses a 256-ID
stack window and an additive storage_browseTrackIds range accessor, avoiding
record/label materialisation and whole-view allocation. Existing legacy array
APIs remain available. Scroll/coast viewport mechanics are unchanged.
Disk previews require a writable card; failed writes retain live playback.

RAM (ID storage only, source arithmetic; no hardware heap measurements):

| Tracks | Old preview heap | New preview resident | Old playView heap | New playView stack |
| --- | ---: | ---: | ---: | ---: |
| 2,000 | 4,000 B | 528 B ESP32 / 536 B host | 4,000 B | 512 B |
| 10,000 | 20,000 B | 528 B ESP32 / 536 B host | 20,000 B | 512 B |

No growth with N; resident addition is one cursor plus fixed bookkeeping,
below 1 KB. A1 live cursor/audio order, favourites CRCs and bounded M3U key
scratch are unchanged and excluded. Preview build still scans the source;
allocations for paths/File objects are bounded but their count scales with N.
