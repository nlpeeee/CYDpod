# CY-116C: fast catalogue validation

From 4112e82. No device operations; no measured SD timing or hardware heap claim.

CYDCAT2 adds a 4 B CRC trailer for eight evenly spaced 512 B body windows,
including first/last. Header CRC, magic, exact section offsets/counts and file
length remain checked; music-scan signature comparison is unchanged. Full body
CRC and all record/id/group bounds checks remain after rebuild. No new handle,
heap allocation, static buffer or per-track index; existing boot scratch is reused.
CYDCAT1 is fully checked only if no CYDCAT2 slot is usable, then a rebuild migrates
the other slot. Failed/read-only migration keeps the legacy fallback and old cost.

Coverage: the old validator read every body byte for CRC32 and checked all string,
id and group bounds (not semantic order/permutations; CRC collisions possible).
Warm CYDCAT2 checks only 4,096 body bytes: arbitrary unsampled text/id/group
corruption can be missed. A sampled ordinary title-byte flip is rejected; the
unsampled title flip is accepted at boot but rejected by full validation.

WSL: `sh tests/build_catalog_validation.sh` (exit 0).
Measured logical File.read bytes per slot; fixture has one group of each kind;
FAT/stdIO read-ahead excluded. Two CYDCAT2 slots double the after counts; a legacy
fallback adds only 60 B. Disk cost is +4 B per catalogue.

```text

PASS validation bytes tracks=10000 before=14360120 after=4160
PASS validation corruption: header, truncation, sampled byte, offsets rejected; unsampled byte deferred to full checksum

```

RAM in bytes (before -> after; no change):
| structure | 2,000 tracks | 10,000 tracks |
|---|---:|---:|
| boot scratch, temporary | 1,424 -> 1,424 | 1,424 -> 1,424 |
| queue + audio order, resident | 8,000 -> 8,000 | 40,000 -> 40,000 |
| preview, transient | 4,000 -> 4,000 | 20,000 -> 20,000 |

findTrack unchanged: reads 256 B path heads at 712 B record strides. Missing/last
track at 10,000: 10,000 random reads x 3.5 ms = 35 s worst case, 2.56 MB logical
reads (2,000: 7 s). Mutex taken per record. Existing on-card orders sort metadata,
so path binary search needs another index, beyond a few-line optimization.
Remaining: that index and the playback RAM risk (CY-116A).
