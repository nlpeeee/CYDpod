# Synthetic AAC fixtures

These are original mathematical signals generated by `python tools/media_check.py --generate`: 440 Hz on the left, 997 Hz on the right, plus separate channel impulses, at a low digital level. They contain no recordings or user music. The generated signal content is dedicated to the public domain under CC0-1.0; this does not change the licenses of FFmpeg, AAC implementations, or the Helix dependency.

`stereo-{128,192,256}.aac` are AAC-LC, 44,100 Hz, stereo ADTS. `reject-*` exercise unsupported profile/rate/channels, malformed input and a truncated final frame. `reject-main.aac` is a deliberately changed seven-byte ADTS header, not a claimed valid AAC-Main encode. The two M4A files contain the same synthetic 192 kbit/s AAC in moov-first and moov-last layouts; **this probe rejects both containers**, pending integration of an existing bounded reader.

`verification.json` records SHA256 hashes and host verification against the pinned Helix decoder and FFmpeg reference PCM. It is evidence for these generated files only. Raw PCM and host build outputs go in `tests/out/` and are reproducible, not fixture inputs. `tests/build_host.cmd` discovers installed Visual Studio C++ tools with `vswhere` and selects x86 for the upstream decoder's inline assembly. This run used Visual Studio 18 BuildTools/MSVC 14.50.35717; no compiler or media tool is installed by these scripts.
